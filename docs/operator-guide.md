# 运营工作台操作指南

本指南对应当前工作台的本地业务流程。真实数据源、模型、OAuth 和平台发布需分别完成连接与联调；页面显示“待连接”时，不会生成虚构来源、账号或发布结果。

## 手动创建与交付

1. 登录后进入“运营总览” `/operations`。各卡片按活动的平台变体统计；点击卡片查看对应列表，再打开活动。原有“工作台”入口仍可使用。
2. 到“商品库” `/products` 核对自家商品、已确认事实版本及主图。待确认的属性不要写成确定卖点。修改事实会产生新版本，已有活动不会自动换用新事实。
3. 点击“创建活动” `/campaigns/new`。来源参考可跳过；即使来源未连接，也能选择自家商品。依次核对事实版本，选择抖音、小红书或双平台，填写可选的创作方向及本轮模型调用次数上限，然后确认启动。来源只供创作参考，不会成为商品事实；当前生成配方对所选来源按排序使用一条参考。
4. 在活动详情查看每个平台的步骤、媒体、文案、事实引用、质检阻塞和预算使用。两平台分别推进；一侧失败不妨碍处理另一侧已完成内容。草稿可在详情手动启动。缺少模型连接时按页面提示处理，系统不会假装生成成功。
5. 从详情进入“编辑与审核”。编辑文案或媒体后须审核新版本；旧批准不自动继承。可对明确可重做的失败步骤执行局部重做。状态为“结果未知”时先核查请求和外部结果，不使用盲目重试。
6. 当前版本审核通过后，可“导出当前已审核版本”下载素材包及交付清单。抖音包含视频、封面与消费者文案；小红书包含封面、有序内容卡与消费者文案。清单记录活动、平台、版本、审核时间、文件顺序和各文件 SHA-256。导出成功只是素材交付，**不等于已发布**。也可进入“发布安排”；缺少有效发布连接或权限时按页面缺项处理，不要将任务状态解释为平台公开发布。

预算数字均为**模型调用次数**，不是货币金额。商品事实、媒体或审核状态不足时，生成、审核、导出或发布安排会给出相应阻塞原因。

## 定时运营计划

在“运营总览”进入“运营计划与执行记录” `/operation-plans`。计划可配置启用状态、IANA 时区和本地执行时间、可选来源、商品范围、目标平台、每日活动上限、每日模型调用次数上限、单活动生成预算，以及是否自动推进。未启用自动推进时只创建活动草稿；启用后也最多推进到**待人工审核**，不会自动批准或发布。有来源但没有明确的商品对应规则时，执行记录会等待人工关联；无来源时按所选自家商品范围创建。

保存并启用计划只允许调度器领取到期窗口；调度器是独立进程，部署时**默认关闭**，不会随 API 自动启动。完成部署配置与迁移后，从仓库根目录运行 `docker compose --env-file deploy/stack.env --profile scheduler up -d operation-scheduler` 启动周期检查；单次检查可在已配置的后端运行环境、以 `backend` 为工作目录运行 `python -m app.operation_scheduler --once`。停止周期检查时，从仓库根目录运行 `docker compose --env-file deploy/stack.env --profile scheduler stop operation-scheduler`。生成 Worker 与发布 Worker 仍分别控制。`PUBLISH_LIVE` 保持 `0` 时不执行真实平台发布；没有模型连接时自动生成会停在待连接。

进入某条计划的“执行记录”，可以查看该轮的配置快照、来源与排序依据、实际取得条数、阻塞原因和已创建活动。`待人工选择`时选定来源条目与自家商品并确认关联；`待连接`、`待补资料`、`预算触顶`、`来源无结果`等状态应先处理原因，再显式“继续这一轮”。`执行中断`时先核查在途采集及对应批次，再决定是否继续。错过的窗口只记录，不自动补跑；在具体记录中确认后才补跑所示轮次。暂停计划会阻止后续新活动创建，已开始的活动仍按原状态机处理。

每日额度按**实际创建活动当日、计划时区的日期**计算；本轮的商品范围、平台和单活动预算保留创建该轮时的快照。调整每日额度后可人工继续受阻轮次，但不会自动补发旧排期。计划执行记录中的“已创建活动”也不代表内容已审核或已发布，后续仍从活动详情进入人工审核和交付。
