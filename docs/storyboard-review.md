# 三镜头首帧与视频审核

在已完成现有抖音活动生成的审核页开启“三镜头版本”。原 FFmpeg 成片流程保留；三镜头是独立审核模式，导出三组首帧与各自 5 秒视频，**不拼接成一条成片**，也不自动发布，当前三镜头模式禁止发布排期。

每个镜头按“生成首帧 → 人工通过/退回 → 生成本镜头视频 → 人工通过/退回 → 锁定”推进。已锁定的镜头必须先显式解锁才能局部重做。重做首帧会使该镜头的视频失效；重做视频保留该镜头已审首帧；另外两个镜头不变。活动按 `expected_version` / `If-Match` 检查并发，每次用户操作产生新变体版本。生成任务只更新自身状态，旧任务晚完成不会写入当前变体；只有当前绑定任务的成功输出经人工审核后才进入新版本。

三镜头均有已审核首帧、已审核视频且锁定，才允许活动审核通过。导出只接受当前有效批准版本，ZIP 中为 `shots/01..03-first-frame`、`shots/01..03-video`、文案、`storyboard.json` 与含逐文件 SHA-256 的 `manifest.json`。manifest 的 `media_scope=three_reviewed_shots_not_composited` 明确交付边界。新事实须新建活动，旧分镜版本不会悄悄套用新事实。原流水线的“按步骤重做”不适用于三镜头模式。

实际生成由项目现有 `GenerationTask` worker 和 `ark.py` 执行。项目根目录 `.env` 需有有效 `ARK_API_KEY`、`ARK_IMAGE_ENDPOINT`，视频另需 `ARK_VIDEO_ENDPOINT`；配置非空不代表有权限或免费额度。页面逐次提交，每张图/每条视频占用活动生成预算 1 次，开启时须至少余 6 次。结果未知或仍运行的任务禁止盲目重做。当前本地环境尚未完成真实模型与 PostgreSQL/对象存储联调；不能把模拟任务测试解释为真实生成成功。
